# 변경 기록

## 설치 방식
- npx 대신 `%LOCALAPPDATA%\openai-gpt-image-mcp` 고정 폴더에 설치: 시작 시 npm 저장소 접속이 필요 없어지고(차단 시 72초 → 0.6초), 부품 버전이 흔들리지 않게 하기 위해
- `server\package.json`, `server\package-lock.json` 추가 후 `npm ci`로 설치: 1.4.0을 고정해도 better-sqlite3 등 하위 부품은 고정되지 않았기 때문에
- Claude 실행 명령을 `cmd /c npx`에서 node 직접 실행으로 변경: 고정 폴더의 서버를 바로 띄우고, 앱이 PATH를 늦게 읽어도 동작하게 하기 위해
- 기존 npx 설정이 있으면 자동 교체: 예전 방식으로 등록된 노트북도 다시 설치만 하면 되게 하기 위해
- 임시 폴더(`.new`)에 설치·검증 후 교체: 실패해도 기존 설치가 망가지지 않게 하기 위해
- `npm ci --ignore-scripts` + `prebuild-install` 직접 실행: 부품 다운로드 실패 시 node-gyp가 Python 설치 관리자를 실행하는 것을 시험에서 확인했기 때문에
- `uninstall.bat`, `uninstall-gpt-image-mcp.ps1` 추가: 설정 항목, 권한, 설치 폴더를 지우고 키가 든 백업 삭제 여부를 묻기 위해
- 설치 검사에 서버 시작 확인(initialize 응답) 추가: 부품 일부가 없어도 "이미 설치됨"으로 건너뛰어 재설치로 고쳐지지 않았기 때문에
- 임시 폴더 삭제 실패를 결과에서 분리: npm 실패 원인이 "파일 사용 중" 안내로 덮일 수 있었고, 설치 성공 뒤 옛 폴더 삭제 실패가 실패로 보고됐기 때문에
- npm을 `cmd /d`로 실행: conda 등이 등록한 cmd 자동 실행 명령이 폴더나 PATH를 바꾸면 엉뚱한 곳에 설치될 수 있기 때문에
- PATH를 다시 만들 때 빈 항목 제거: PATH가 `;`로 시작하면 cmd가 npm을 찾지 못하는 것을 시험에서 확인했기 때문에
- 설정 파일이 JSON이지만 모양이 다르면(배열, null, mcpServers가 객체가 아님 등) 손상된 파일처럼 건드리지 않음: 시험에서 설치 스크립트가 원인 없는 오류로 멈췄기 때문에
- 분류되지 않은 npm 실패에도 다음 행동 안내 추가: Node 22의 npm은 접속 실패 시 `Exit handler never called`라는 원인 불명 문구만 남기는 것을 시험에서 확인했기 때문에
- 마지막에 설정 등록이 그대로 있는지 다시 확인: Claude를 켠 채 진행하면 Claude가 설정 파일을 덮어써 등록이 조용히 사라질 수 있기 때문에
- 등록 재확인을 시험 결과 안내보다 먼저 실행: 크레딧 부족 등 "재설치 불필요" 안내가 나오면 등록이 사라진 사실이 가려졌기 때문에
- npm이 네트워크 외 이유로 실패하면 새 임시 캐시로 한 번 더 시도: 시험 중 npm 캐시의 `EEXIST`(파일이 이미 있음) 오류로 설치가 실패한 것을 확인했기 때문에
- better-sqlite3 부품 다운로드를 10·20·40·60초 기다리며 최대 5번(약 2분) 시도하고 3번째부터 새 임시 캐시 사용, 실패 안내에 "몇 분 뒤 다시 실행" 추가: 시험 중 GitHub 일시 오류가 두 번 있었고(한 번은 몇 분간 7번 연속 실패), 3번 시도로도 실패한 적이 있으며, npm 캐시가 망가진 경우 이 단계도 실패했기 때문에
- 이미 설치된 경우에도 남은 임시 폴더(`.new`) 정리: 중간에 멈춘 설치의 임시 폴더가 계속 남았기 때문에
- 32비트 등 x64가 아닌 Node 차단: 이미지 부품이 x64용으로만 시험됐기 때문에
- `npm ci --include=optional`: 사용자 npm 설정에 선택 부품 제외가 있으면 sharp의 윈도우용 파일이 빠지기 때문에
- 사용자 환경변수 `NODE_OPTIONS`를 설치·제거 중에는 비우고, 등록하는 서버 설정에도 빈 값으로 지정: 잘못된 값이 있으면 모든 node 실행이 실패해 원인 없는 "Node.js 지원 안 함" 안내가 나오는 것을 시험에서 확인했기 때문에
- 등록하는 node 경로를 `process.execPath`(실제 node.exe)로 변경: PATH 앞에 `node.cmd` 같은 대리 실행 파일이 있으면 그 경로가 등록되어 Claude가 서버를 켜지 못했기 때문에
- `cmd.exe`, `taskkill.exe`를 System32 절대 경로로 실행: PATH에 System32가 없으면 npm 설치가 `spawnSync cmd ENOENT`로 실패했기 때문에
- `npm ci`에 `--global=false --dry-run=false --offline=false --package-lock=true` 지정, 설치 후 부품이 실제로 있는지 확인: 사용자 npm 설정에 따라 `ECIGLOBAL` 오류가 나거나, 아무것도 설치하지 않고 엉뚱한 "GitHub 다운로드 실패" 안내가 나왔기 때문에
- 설정을 바꾸기 전에 이미지 저장 폴더를 만들 수 있는지 확인: 같은 이름의 파일이 있으면 "Node.js를 다시 설치하라"는 잘못된 안내가 나왔기 때문에
- 붙여넣은 키에서 보이지 않는 문자, 앞뒤 따옴표, `Bearer ` 접두어 제거: 메신저·문서에서 복사한 키가 형식 오류로 5번 거부됐기 때문에
- npm과 부품 다운로드에서 프록시 설정(`HTTPS_PROXY` 등, npm `proxy`)을 무시하고 직접 접속: 직접 접속 확인은 통과했는데 남아 있던 작동하지 않는 프록시 설정 때문에 npm이 실패하는 것을 시험에서 확인했기 때문에
- npm을 PATH의 `npm.cmd` 대신 등록할 node.exe 옆의 `npm-cli.js`로 실행: PATH 앞쪽에 다른(오래된) Node의 npm이 있으면 그 npm으로 설치되다 실패하는 것을 시험에서 확인했기 때문에
- `npm ci`에 `--registry=https://registry.npmjs.org/ --os=win32 --cpu=x64` 지정: 접속 확인한 저장소와 다른 회사 내부 저장소 설정이나 CPU 지정(`cpu=arm64`)이 있으면 설치가 실패하거나 엉뚱한 부품이 깔렸기 때문에
- better-sqlite3 부품을 받을 때 `--runtime=node --target=현재 버전 --arch=x64 --platform=win32` 지정, Electron용 환경변수 무시: Electron 개발 설정이 남아 있으면 맞지 않는 부품을 받아 "서버 부품을 불러오지 못했다"로 실패했기 때문에
- 설치 전 디스크 남은 공간(500MB) 확인, npm의 `ENOSPC`를 "디스크 공간 부족"으로 안내: 디스크가 가득 차면 "인터넷 연결을 확인하라"는 잘못된 안내가 나왔기 때문에
- 다른 계정의 관리자 권한으로 실행하면 중단(설치·제거 모두): 그 계정의 사용자 폴더에 설치되어 지금 로그인한 사용자의 Claude에는 연결되지 않기 때문에
- 회사 관리 Claude 설정(`managed-mcp.json`, `deniedMcpServers`/`allowedMcpServers`)이 있으면 경고: 설치는 끝나도 Claude에서 도구가 안 보일 수 있기 때문에
- 설치 경로에 `;`가 있으면 중단: 이미지 부품(sharp)이 그런 경로에서 DLL을 불러오지 못하는 것을 시험에서 확인했기 때문에 (Windows 사용자 이름에는 `;`를 쓸 수 없어 경로를 따로 바꾼 경우에만 해당)
- 제거 후에도 등록이 다시 생겼는지 확인하고 안내: Claude를 켠 채 제거하면 Claude가 설정을 되살려 지워진 서버를 가리키게 되기 때문에
- 제거 시 설정에서 항목을 지우지 못하면 설치 폴더도 남김: 설정은 남고 폴더만 지워져 Claude가 없는 서버를 가리켰기 때문에
- 제거 시 중간에 끊긴 설치가 남긴 시험 프로세스와 임시 폴더도 정리: 제거 후에도 남았기 때문에
- npm이 네트워크 오류로 실패하면 15초 뒤 한 번 더 시도, 실패 안내에 npm 오류 코드 줄을 앞에 표시: Node 24 시험에서 접속 확인 직후 npm이 일시적인 네트워크 오류로 두 번 실패했고, 안내에는 뒷부분만 남아 오류 코드를 알 수 없었기 때문에
- PATH의 node가 실행되지 않으면 "Node.js가 실행되지 않습니다"로 안내: 버전 확인이 빈 값이 되어 "예상하지 못한 오류: null-valued expression"으로 멈췄기 때문에
- npm 설치 후 sharp의 윈도우용 부품까지 있는지 확인하고, 없으면 새 캐시로 한 번 더 설치, 그래도 없으면 "이미지 부품을 받지 못했다"로 안내: npm은 선택 부품 다운로드가 실패해도 성공으로 끝내서, 시험에서 "Node.js를 다시 설치하라"는 잘못된 안내가 나왔기 때문에
- "서버 부품을 불러오지 못했습니다" 안내에 백신 검역소 확인을 먼저 넣음: 이 오류는 Node.js 문제보다 부품 파일이 빠진 경우가 많기 때문에
- `install.bat`, `uninstall.bat`이 항상 64비트 PowerShell을 실행(`Sysnative`): 32비트 프로그램(일부 압축 프로그램 등)에서 실행하면 32비트 PowerShell이 떠서 회사 관리 설정 위치를 `Program Files (x86)`에서 찾는 것을 시험에서 확인했기 때문에. 관리 설정 위치도 `ProgramW6432` 기준으로 변경
- PowerShell 제한 언어 모드(회사 AppLocker/WDAC)면 처음에 이유를 알리고 중단: 그 모드에서는 원인 모를 오류로 멈추기 때문에
- 스마트 앱 컨트롤이 켜져 있으면 경고하고, 부품 로드 실패 안내에 그 가능성을 표시: 서명 없는 이미지 부품이 차단될 수 있기 때문에 (이 노트북에서는 켜 볼 수 없어 실제 차단 여부는 확인 못 함)
- 지원하지 않는 Node 버전 안내에 실제로 쓰인 node 경로 표시: Node 24를 설치해도 PATH 앞쪽의 예전 Node가 계속 쓰이는 경우 사용자가 원인을 알 수 없기 때문에
- 환경변수 `OPENAI_IMAGE_OUTPUT_DIR`이 전체 경로가 아니면 무시하고 기본 위치 사용: 상대 경로가 그대로 등록되어 Claude가 시작한 폴더 기준으로 이미지가 흩어지는 것을 시험에서 확인했기 때문에
- 이미지 기록 DB를 이미지 폴더 안(`data`)이 아니라 `%LOCALAPPDATA%\openai-gpt-image-mcp-data`에 두도록 `HISTORY_DB_PATH` 지정, 제거 시 함께 삭제: 회사에서 다운로드 폴더가 네트워크 폴더로 옮겨졌거나 OneDrive로 동기화되면 SQLite(WAL)가 잠기거나 망가질 수 있기 때문에 (실제 재현은 못 함). 이전 설치의 기록은 새 위치로 옮겨지지 않음
- API 키 확인을 PowerShell `Invoke-RestMethod`에서 node로 옮김: 회사 PC에 PowerShell 모듈 로깅이 켜져 있으면 명령의 매개변수(키가 든 헤더)가 이벤트 로그에 남기 때문에
- 폴더 삭제에 `fs.rmSync` 대신 자체 삭제 함수 사용(설치·제거): Node 24.0.0에서 `fs.rmSync`가 한글 등 ASCII가 아닌 경로에서 프로세스를 강제 종료(0xC0000409)시켜, 한글 사용자 이름 PC에서 "서버 설치 중 오류"로 실패하는 것을 시험에서 확인했기 때문에
- 설정 파일을 읽고 쓸 때 숫자를 원문 그대로 보존(`JSON.rawJSON`): 2^53을 넘는 정수나 긴 소수가 반올림되어 바뀌는 것을 시험에서 확인했기 때문에
- 하드링크된 설정 파일은 제자리에 덮어쓰기: 설정 동기화 도구가 만든 링크가 임시 파일 교체 방식 때문에 끊어졌기 때문에
- 백업 이름의 날짜를 언어 설정과 무관한 숫자로, "최근 3개 보관"은 이 설치가 만든 이름 형식만 정리: 태국어 설정에서 연도가 2569로 기록되어 순서가 틀어지고, 사용자가 직접 만든 `.claude.json.backup-…` 파일이 지워질 수 있었기 때문에
- 키 확인을 대소문자 구분 비교로: 터키어 언어 설정에서 I/i가 들어간 정상 키가 5번 모두 거부됐기 때문에
- 키 입력에서 `.env`의 `OPENAI_API_KEY=` 줄 자동 정리, Anthropic 키(`sk-ant-`)·조직/프로젝트 ID·두 번 붙여넣기를 구분해 안내: 원인을 알 수 없는 "형식 아님"이나 401로만 끝났기 때문에
- 설치 위치·임시 폴더·Claude 설정 폴더의 쓰기 권한을 먼저 확인하고 "쓸 권한 없음"으로 안내: 권한이 막힌 PC에서 "다른 프로그램이 사용 중"이라는 잘못된 안내나 원인 모를 오류가 나왔기 때문에
- 설치 경로가 200자를 넘으면 중단: 경로가 너무 길면 Windows가 그 안에서 프로그램을 시작하지 못해 npm이 `ENOENT`로 실패했기 때문에
- 시작 전 접속 확인에 `release-assets.githubusercontent.com`(부품 실제 다운로드 주소) 추가: 이 주소만 막힌 회사망에서 npm을 다 받은 뒤에야 늦게 실패했기 때문에
- 보안 연결 오류 안내에 "공용 와이파이 로그인 화면" 추가: 호텔·카페 와이파이의 로그인 화면도 인증서 오류로 보이기 때문에
- `npm ci`에 `--cafile`(Node 기본 인증서 목록), `--fetch-timeout=300000`, `--fetch-retries=5` 지정: 사용자 npm 설정의 깨진 `ca`, 극단적인 시간 제한, 재시도 0회 때문에 설치가 실패했기 때문에
- OpenAI 403 `unsupported_country_region_territory`를 "지원하지 않는 지역(VPN)"으로 안내: "키 권한을 All로" 라는 잘못된 안내가 나왔기 때문에
- 분류되지 않은 이미지 생성 실패를 "설치는 끝났지만 시험 이미지를 만들지 못했다"로 안내: "시험에 실패했습니다 (GENFAIL)"만으로는 설치가 끝났는지 알 수 없었기 때문에
- 이미지 기록 DB가 손상됐으면 따로 보관하고 새로 만들기, DB 오류 안내를 "Node.js 재설치"에서 "기록 파일"로 변경: 손상된 DB 때문에 모든 이미지 요청이 실패하고 재설치로도 고쳐지지 않았기 때문에
- 같은 이름으로 다른 서버가 등록돼 있으면 교체 사실과 예전 설정을, 다른 이름으로 같은 패키지가 있으면 중복을, settings.json에 이 도구 차단 규칙이 있으면 그 사실을 경고: 모두 조용히 진행되어 사용자가 원인을 알 수 없었기 때문에
- 제거 시 다른 위치(`CLAUDE_CONFIG_DIR` 전후)의 Claude 설정에 항목이 남아 있으면 경고
- `install.bat`/`uninstall.bat`에서 스크립트가 시작조차 못 하면(실행 정책·백신 차단) 한글로 안내: 영어 오류만 보이고 창이 닫혔기 때문에
- 설치와 제거를 한 창만 실행: 두 번 더블클릭하면 두 번째 창이 첫 번째 창의 임시 폴더를 지웠기 때문에

## 시작 전 검사
- Node 허용 목록(22, 24, 26): 안내상 18 이상이지만 18, 20은 실제 실패했고 23 등은 미리 빌드된 파일이 없기 때문에
- ARM 윈도우 감지 후 중단: sharp 0.33.5에 ARM용 파일이 없기 때문에
- registry.npmjs.org, github.com, api.openai.com 접속 확인 후 막힌 곳을 이름으로 안내: 회사망에서 원인 모를 실패를 막기 위해
- 접속 실패 이유를 표시하고 인증서 오류를 따로 안내: 백신·보안 장비의 HTTPS 검사나 날짜 오류가 방화벽 문제처럼 보였기 때문에
- 접속 확인 스크립트가 실행되지 못하면 중단: 실행 실패를 통과로 잘못 처리하던 문제를 고치기 위해
- 입력 불가 환경 감지 후 즉시 종료: 표준입력이 넘어오면 키 입력에서 멈추던 문제를 고치기 위해
- 키 입력 전에 서버를 설치하도록 순서 변경: 설치가 실패하면 Claude 설정을 건드리지 않게 하기 위해

## 시험 단계
- 오류 분류를 HTTP 상태 코드와 API 오류 코드 기준으로 변경: 문장 속 단어 때문에 요청 과다를 크레딧 부족으로 오인했기 때문에
- 시험 때만 API 응답의 상태·오류 코드를 기록: 도구가 돌려주는 문장에는 오류 코드가 빠져 있기 때문에
- 요청 과다, 안전 정책 거부, 시간 초과, OpenAI 서버 오류 안내 추가: 사용자가 원인을 구분하게 하기 위해
- tools/list로 도구와 인자를 확인한 뒤 호출: 서버 구성이 다르면 정확히 알리기 위해

- 시험 이미지 모델을 `gpt-image-2`로 지정: 패키지 기본값 `gpt-image-1`이 실제 키 시험에서 "does not exist"로 실패했기 때문에 (OpenAI 공지상 2026-10-23 종료 대상)
- 설치 폴더 사본의 기본 모델을 `gpt-image-2`로 변경: 패키지에 기본값 설정이 없어, Claude가 모델을 지정하지 않으면 계속 실패하기 때문에
- 모델을 쓸 수 없을 때의 안내 추가: 일반 실패로 표시되어 원인을 알기 어려웠기 때문에

## 파일 처리
- 다운로드 폴더를 셸 폴더 기준으로 구해 `OPENAI_IMAGE_OUTPUT_DIR`로 지정: OneDrive 등으로 옮긴 노트북에서 이미지를 못 찾는 문제를 막기 위해 (패키지가 이 값을 읽는 것을 `path.js`에서 확인)
- `settings.json` 수정 전 백업, 손상되면 권한 추가만 건너뜀: 사용자 설정을 잃지 않고 설치는 끝내기 위해
- 키가 든 백업은 최근 3개만 보관: 실행할 때마다 키 사본이 쌓이던 문제를 고치기 위해
- 잠긴 파일을 2초 간격으로 최대 5번 재시도하고 한글로 원인 안내: 잠깐 잠긴 경우 실패하지 않게 하기 위해
- 파일 경로에 `-LiteralPath` 사용: 경로에 `[ ]`가 있으면 실패하던 문제를 고치기 위해
- `CLAUDE_CONFIG_DIR` 폴더가 없으면 생성하고, 백업이 없을 때 "백업이 남아 있다"고 하던 안내 수정
- 같은 이름의 로컬 범위 설정과 프로젝트 `.mcp.json`을 찾아 경고: 그 폴더에서는 다른 설정이 쓰일 수 있기 때문에
