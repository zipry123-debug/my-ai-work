# 이상 상황 추가 시험 기획서 (20개)

대상: `인스타툰 이미지 MCP 설치` (install.bat / uninstall.bat)
기존 시험 32개와 겹치지 않고, 이 노트북에서 실제로 재현할 수 있는 것만 골랐다.
모든 시험은 임시 폴더(가짜 홈, 가짜 설정)에서 하며, 실제 설정·실제 설치·실제 이미지는 건드리지 않는다. 진짜 이미지 생성(과금)은 하지 않는다.

## 판정 기준
- **통과**: 설치가 정상으로 끝나거나, 사용자가 다음에 할 일을 알 수 있는 안내와 함께 멈춘다. 이때 설정 파일을 망가뜨리지 않고 키를 엉뚱한 곳에 남기지 않는다.
- **실패**: 원인 없는 오류, 잘못된 안내, 설정 손상, 키 유출, 멈춤(무한 대기)

# 2차 추가 시험 (14개, 2026-11-06, Node 26)

코드를 다시 읽고 고른 후보 14개. 수정 전 코드로 먼저 돌려 실패한 것만 실제 문제로 보고 고쳤다.

| # | 상황 | 수정 전 | 수정 내용 | 최종 |
|---|---|---|---|---|
| B1 | 경로에 `! ^ ; , = $ #` | bat은 정상. 설치 경로에 `;`가 있으면 sharp가 DLL을 못 불러와 "서버 부품을 불러오지 못했다"로 실패 (`!^,=$#`는 정상) | `;`가 있으면 이유를 알리고 중단 (Windows 사용자 이름에는 `;` 불가라 드묾) | 통과 |
| B2 | 설치 중 디스크 가득 참 (ENOSPC) | "인터넷 연결을 확인하라"는 잘못된 안내 | "디스크 공간 부족" 안내, 쓸모없는 재시도 생략 | 통과 |
| B3 | 설치 전부터 공간 부족 | 검사 없이 진행 | 시작 전 500MB 확인 | 통과 |
| B4 | PATH 앞에 다른(오래된) npm | 그 npm으로 실행돼 실패 | node.exe 옆의 npm을 직접 실행 | 통과 |
| B5 | 접속 불가한 회사 내부 npm 저장소 설정 | 첫 시험은 캐시 덕분에 통과로 보임 | 접속 확인한 공식 저장소로 고정 | 통과 (캐시 비우고 확인) |
| B6 | npm engine-strict | 통과 | - | 통과 |
| B7 | npm cpu=arm64 | 맞지 않는 부품이 깔려 실패 | `--os=win32 --cpu=x64` | 통과 |
| B8 | npm before 날짜 | 통과 | - | 통과 |
| B9 | Electron 환경변수 | 맞지 않는 부품을 받아 실패 | 부품 다운로드에 런타임·버전·CPU 명시, 해당 변수 무시 | 통과 |
| B10 | 다른 계정의 관리자 권한으로 실행 | 그 계정 폴더에 설치 | 설치·제거 모두 중단하고 안내 (같은 계정 관리자 실행은 허용) | 통과 |

| B12 | Claude를 켠 채 제거 → 등록 되살아남 | "제거 완료"만 표시 | 제거 후 재확인하고 안내 | 통과 |
