# 입지 분석 웹사이트 인수인계

갱신일: 2026-11-04 (저녁, 지도 이어 보기와 칸 그리기 방식 변경을 웹에 올린 뒤)

## 한눈에 보기

- **목적:** 레터링 케이크 매장 후보 칸을 찾는 입지 분석 웹사이트를 만들어 링크로 공유한다. 첫 지역은 안산이었고, 전국으로 넓히는 중이다.
- **공유 대상(사용자 발언):** 링크는 선배 한 명에게만 준다. 불특정 다수에게 배포하지 않는다. "처음 연 사람 대부분" 같은 다수 방문자 전제로 제안하지 않는다. 다만 한 명에게 주는 것도 외부 제공이므로 약관 확인이 면제되지 않는다.
- **범위(사용자 지시):** 경력, 자금, 대출, 가족 동의, 목표 수익 같은 창업자 정보와 창업 손익 분석은 다루지 않고 묻지 않는다. `창업분석_에이전트_프롬프트_v2.md`의 "먼저 받을 정보"보다 이 지시가 우선한다.
- **자동화 원칙(사용자 지시):** 전국 확장을 전제로 판정은 자동화한다. 사람이 가게를 하나씩 확인하는 단계를 필수로 두지 않는다. 불확실한 값은 `추정`, `미확인`으로 화면에 구별한다.
- **이어 보기 원칙(사용자 지시, 2026-11-04):** 어느 지역으로 들어가도 옆 지역 칸이 이어서 보여야 한다. 첫 화면의 지역 선택은 "시작할 지역을 고르거나 먼 곳으로 편하게 이동"하기 위한 것이다. 그 지역만 보겠다는 뜻이 아니다.
- **현재 상태:** 시험판 `https://cake-map-ansan.pages.dev`(Cloudflare Pages + Access 로그인)에 최신 버전이 올라가 있다. 사용자가 웹에서 확인하고 "성공"이라고 했다. 지금은 사용자 본인만 들어갈 수 있고, 선배 이메일은 아직 넣지 않았다.
- **자료가 있는 지역(13곳):** 세종, 대전 5개 구(완성형 기준 지역), 시험 지역 7곳(안산, 서울 마포구·중구, 청주, 양평, 목포, 증평). 전국 나머지 약 217곳은 아직 만들지 않았다(사용자 지시: 아직 하지 마).
- **진행 위치:** 세종·대전 완성형 작업과 이어 보기 구조 변경까지 끝났다. 다음 할 일은 맨 아래 "다음 단계" 참고.

## 작업 방식 (사용자 지시)

1. 짧고 정확하게 답하고, 사실과 추측을 구분한다. 묻지 않은 계획이나 대안을 늘어놓지 않는다.
2. **답과 진행 안내는 모두 한국어로만 쓴다.** 작업 중 짧은 안내도 영어로 쓰지 않는다(사용자가 여러 번 지적함).
3. 파일이나 시스템을 새로 만들기 전에 보고하고 승인을 받는다. 파일을 내려받기 전에도 파일명, 출처, 크기를 알리고 승인을 받는다.
4. 사용자와 문답하며 점진적으로 발전시키고, 정할 것은 하나씩 묻는다. 설명은 쉽게 한다. 사용자가 "더 쉽게"라고 하면 용어를 빼고 다시 설명한다.
5. 화면을 어떻게 바꿀지 물을 때는 그림(목업)으로 보여 준다.
6. 화면을 고치면 브라우저에서 직접 확인한 뒤 보고한다. 못 한 확인은 그대로 말한다.
7. API 키는 채팅에 받지 않고, 출력이나 파일에 남기지 않는다. 사용자가 메모장을 열어 달라고 하면 `입지조사/설정.env`를 내용을 읽지 않고 연다.
8. 파일 삭제: 사용자가 요청하면 Claude가 휴지통으로 옮기고, 휴지통 비우기는 사용자가 한다. 잘못 만든 자료나 바꾼 자료는 지우지 않고 이름을 바꾸거나 보관 폴더로 옮긴다(예: `보관_옛지역id`, `12110_시험중단.bak`).
9. 조사는 Claude가 먼저 끝까지 한다("다 뒤져서 네가 알아내", "구글링도 포함"). 전화 문의를 먼저 시키지 않는다. 로그인이 필요하면 사용자가 브라우저 창에서 직접 로그인하고, Claude는 읽기만 한다. 공공데이터포털 활용신청은 사용자가 하고, Claude는 신청 페이지 링크와 활용목적 문구(복사용)를 준다.
10. 사용자가 진행 상황을 물으면 진행률과 단계별 상태를 짧게 보고한다.
11. 사용자가 "인수인계 파일 갱신"을 요청하면 이 파일을 현재 상태로 다시 쓰고, 새 채팅 시작 문구를 함께 준다.
12. 사용자가 시험의 목적을 짚으면 그 목적 기준으로 결과를 다시 정리한다.
13. **오류 없이 꼼꼼하게(사용자 지시, 반복 강조):** 자료를 만들 때 중복 집계·누락을 자동 검사로 막고, 지역마다 결과를 직접 점검한 뒤 보고한다. 저번 인구 중복 집계(오창읍 230만 명) 같은 일이 다시 없어야 한다.
14. 사용자가 "주소 줘/올려"라고 하면 복사용 코드 블록으로 준다.

## 2026-11-04 과정

1. **지역 선택 첫 화면(사용자 선택: C안 첫 화면 목록):** 주소만 열면 시도별 지역 목록과 검색창이 나온다. 누르면 `?region=<시군구 코드>`로 지도가 열린다.
2. **지역 id를 시군구 코드로(사용자 승인):** 안산 41270, 마포 11440, 청주 43110, 양평 41830 등. 일반구가 있는 시는 시 코드로 묶는다(안산시상록구 41271 + 단원구 41273 → 41270). 옛 영문 id 파일은 `보관_옛지역id` 폴더로 옮겼다.
3. **지역 목록 파일(사용자 승인):** `dist/data/regions/index.json`. `build_region.py`가 자동으로 갱신한다. 지역마다 `id, sido, name, builtAt, bounds`. 최상위에 `show: [id...]`를 넣으면 첫 화면에 그 지역만 보인다(지금은 없음 = 13곳 모두 보임).

5. **지역 묶기 오류 수정:** 코드 앞 네 자리로 묶었더니 영동군(43740)과 증평군(43745)이 한 지역이 됐다. 지금은 이름이 "OO시OO구"인 일반구만 시 코드로 묶는다. 전국 230곳.
6. **전국 자료의 새 이름:** 동 경계(2026-10-01판)와 인허가 주소에 `전남광주통합특별시`(코드 12xxx), 인천 `제물포구·영종구·서해구·검단구`가 있다. 옛 시도 이름(광주광역시, 전라남도, 강원도, 전라북도)으로도 함께 검색한다(건수는 거의 0).
7. **오류 방지 검사 추가:** 아래 "자동 검사" 참고. 시험 중 API가 오류 표시 없이 빈 결과를 주는 것을 발견했다(강남구가 0건으로 왔다가 다시 물으면 2,045건).
8. **4년 전 인구 이어 붙이기:** 코드가 바뀐 지역(목포 46110 → 12110 등)은 2022년 인구가 옛 코드로 온다. 동 이름이 같은 지금 동에 붙인다. 못 붙인 동은 감소율 `미확인`(0%로 두지 않음). 세종 나성동·어진동·집현동이 미확인.

10. **같은 가게 중복 집계 수정:** 상가 자료 "파리바게뜨"와 인허가 "파리바게뜨 가오은어송점"이 같은 자리인데 두 번 셌다. 30m 안에 이름이 비슷하면(공백·괄호 빼고 한쪽이 다른 쪽을 포함하거나 앞 4글자 같음, 파리바게트→파리바게뜨 통일) 한 곳으로 센다. 안산 판매 138 → 110곳, 모두 충족 137 → **173칸**(검사 기준 갱신함).

## 실행과 수정

- **보기:** `입지조사/실행.bat`을 더블클릭하면 `http://127.0.0.1:8765/map`이 열린다(지역 목록). 특정 지역에서 시작: `http://127.0.0.1:8765/map?region=30140`. 검은 창을 닫으면 서버가 꺼진다.
- **더블클릭 금지:** `지도.html`을 직접 열면 지역 자료와 네이버 인증이 실패한다.
- **수정 위치:** `ansan-location-map-handoff/ansan-location-map-handoff/dist/`에서 고친 뒤 복사한다.
  - `dist/index.html` → `입지조사/지도.html`
  - `dist/data/regions/*.json` → `입지조사/data/regions/` (`build_all.py`는 자동 복사)
- **웹에 다시 올리기(사용자):** Cloudflare 대시보드의 Pages 프로젝트 `cake-map-ansan` → `Create deployment` → Production → `dist` 폴더를 폴더째 끌어다 놓기 → Save and Deploy. 주소는 그대로다. 지금 `dist`는 파일 15개, 약 6.2MB.
- **검사:** 패키지 폴더에서 `node scripts/check.mjs`(안산 기준 **173칸**), `입지조사` 폴더에서 `python -m unittest test_core`.
- **검사 기준:** 판정이나 자료를 일부러 바꾸면 `reference/analysis-baseline.json`의 `snapshot`을 갱신하고, 변경 이유와 새 결과를 사용자에게 설명한다. 갱신은 `scripts/analysis-snapshot.mjs`의 `snapshot(html, region)` 결과를 넣는다. 이 스크립트는 HTML의 `// ---------- 설정`부터 `// ---------- 지도` 사이를 Node에서 돌린 뒤 `addRegion(REGION)`을 부른다.

### 지역 자료 만들기

`입지조사` 폴더에서 실행한다. 폴더 이름과 인자는 모두 **시군구 코드**다(`데이터/지역/<코드>/`).

```bash
python 수집/build_all.py 30110 30140
```

- 코드를 주면 그 지역만, 안 주면 전국 230곳을 차례로 만든다(아직 전국 실행 금지).
- 단계: 동 경계 자르기(`extract_region.py`) → 수집(`collect_region.py`) → 경쟁점 판정(`classify_rivals.py`) → 지도 자료(`build_region.py`, `dist/data/regions/<코드>.json`과 `index.json` 갱신) → `입지조사/data/regions`로 복사.
- 이미 `dist`에 자료가 있는 지역은 건너뛴다. 수집은 받은 단계(`raw/*.json`)를 건너뛴다. 다시 받으려면 해당 raw 파일을 옮긴다.
- 기록: `데이터/전국생성_기록.txt`(지역마다 한 줄: 완료/실패/대기), 자세한 출력 `데이터/전국생성_로그/<코드>.txt`.
- 하루 호출 한도에 걸리면(`QuotaError`, 종료 코드 3) 1시간 기다렸다가 같은 지역부터 다시 한다. 3일 넘게 기다리면 멈춘다. 다른 오류는 기록하고 다음 지역으로 넘어간다.
- 판정이나 지도 자료 규칙만 바꿨을 때(API 재호출 없이): `python 수집/classify_rivals.py <코드>` 후 `python 수집/build_region.py <코드> ../ansan-location-map-handoff/ansan-location-map-handoff/dist/data/regions`. **옆 지역 가게를 세므로 근처 지역을 모두 다시 만들어야 결과가 맞다.**

## 지도 화면 구조 (`dist/index.html`)

- **지역 불러오기:** 확대 11단계 이상일 때 화면 둘레 25%까지 범위가 겹치는 지역을 `index.json`의 `bounds`로 골라 불러온다. 12곳이 넘으면 화면에서 먼 지역부터 내린다(후보가 있는 지역, 선택한 칸의 지역은 남김). 너무 넓게 보면 "지도를 확대하면 이 근처 지역 칸을 불러와요" 안내.
- **칸:** 모든 지역이 전국 공통 200m 격자(EPSG:5179)라 칸 id(`<격자x>_<격자y>`)가 지역이 달라도 겹치지 않는다(13곳 확인). 이웃 칸은 `cellNear`로 지역을 넘어 찾는다. 판정은 칸이 속한 지역의 자료(주변 3km 점 포함)로 한다.
- **그리기:** 화면 둘레 절반까지 덮는 캔버스 한 장. 칸 네 모서리의 웹 메르카토르 좌표를 미리 구해 두고 배율·원점만 적용한다(네이버 변환과 1px 넘게 다르면 네이버 변환 사용). 색마다 따로 판에 불투명하게 400칸씩 칠하고 0.5px 테두리로 틈을 메운 뒤 원래 투명도로 얹는다. 갈색 구역선·분홍선은 SVG.
- **왼쪽 숫자:** 화면에 보이는 칸만 센다. 여러 지역이면 지역별 수를 괄호로 보여 준다. 구역 목록은 화면에 걸친 구역만, 구역은 지역 경계를 넘어 이어진다.
- **출처:** 불러온 지역의 출처를 모아 같은 문구는 한 번만, 지역마다 다른 문구는 `[지역 이름]`을 붙인다.

## 지도의 조건과 시작값

시작값은 사용자가 승인했지만 공식 수치가 아니다. 지역 유형별 기준값은 아직 없다(모든 지역에 같은 값).

| 조건 | 방식 | 판정 내용과 시작값 |
|---|---|---|
| 1. 거주지역 | 필수 | 칸이 주거·상업지역에 걸침, 칸 주변 500m 1,000가구 이상, 동 4년 감소율 20% 이하(미확인이면 통과로 보고 "4년 변화 미확인" 표시), 동 세대수 0 이상 |
| 2. 안내 기준점 | 참고 | 지하철역, 대형마트, 학교, 공공기관, 아파트 중 하나가 300m 안 |
| 3. 대중교통 | 필수 | 지하철 800m 또는 버스 300m 안 |
| 4. 공영주차장 | 참고 | 300m 안 |
| 5. 경쟁·폐업 | 참고 | 반경 500m 안 케이크 판매 추정 2곳 이하(체크 상자를 켜면 미확인 빵집도 더함), 최근 3년 제과점 폐업 10건 이하. 넘으면 분홍 테두리. 옆 지역 가게도 셈 |
| 6. 상가 존재 | 필수 | 칸 안 기존 업소 1곳 이상 |
| 보류 | 필터 | 개발제한구역, 보전지역, 공업지역, 주거·상업이 없는 산단 칸. 갈색, 충족 개수에서 제외 |

- **조건 모드:** 조건마다 `필수 / 참고 / 끔`. 필수를 못 맞추면 회색, 참고를 못 맞추면 칸은 남지만 `모두 충족`에서 빠진다.
- **사용자 결정:** 주차장은 `참고`. 월세·보증금 입력칸과 임대 조건은 다시 넣지 않는다. 민영·OSM·교통안전공단 주차장 자료는 다시 제안하지 않는다. 지역 유형별 기준값은 "일단 괜찮다"(시험 목적이 아님).
- **구청 문의:** 사이트 제작 단계에서는 하지 않는다. 사이트에는 툴팁으로 안내한다.
- **의도적으로 뺀 것:** 종합 점수와 가중치. 유동인구, 소득, 임대료.
- **폐업:** 판정은 제과점영업만 센다. 즉석판매와 휴게음식점은 상호로 걸러 참고 건수로만 표시한다.
- **화면:** 자체 색상, 충족 개수별 색, 범례(휴대폰은 접힘), 구역 목록, 후보 5곳 비교(`조건 비교`, `현장 확인` 탭, `크게 보기`), 네이버 바로가기, 칸 상세창(휴대폰은 아래 창, 손잡이로 접기). 분홍 테두리는 넓게 볼 때 묶음, 14단계부터 칸마다.

## 경쟁점 자동 판정 (`입지조사/수집/classify_rivals.py`)

결과는 `raw/rival_cake.json`(판정과 근거 `basis`). 가맹 브랜드 목록은 `입지조사/데이터/원본/가맹브랜드/브랜드_2025.json`(11,167개)에 받아 두어 외부 호출이 없다.

1. **후보:** 상가 자료의 `빵/도넛` 업종과 케이크 상호, 인허가에만 있는 영업 중 제과점, 즉석판매·휴게음식점의 케이크 상호. 같은 가게는 30m·비슷한 이름으로 합친다.
2. **규칙(순서대로):** 파리바게뜨·뚜레쥬르 → `판매` / 호떡·꽈배기·와플·도넛·떡케이크 상호, 청소·광고 업종 → `제외` / 가맹 브랜드 주요상품명 규칙(판매 27개, 제외 130개 정도) / 상호에 케이크 → `판매`(학원 제외) / 나머지 `미확인`.
3. **한계:** 미확인 대부분은 이름만으로는 알 수 없는 동네 빵집이다. 기본은 판정에서 빠지므로 경쟁이 실제보다 적게 계산된다(체크 상자로 반대 가정을 켤 수 있음). 영업 신고 없는 인스타그램 공방은 후보에 없다. 상호 앞부분 일치라 비슷한 이름의 다른 가게가 잡힐 수 있다(마포구 "뉴욕베이글마켓", 확인 안 함). 한 건물의 같은 가게 여러 매장(성심당 대전역점 1~4)도 한 곳으로 센다.

## 알려진 약점

- **경쟁점:** 미확인(동네 빵집)이 기본 판정에서 빠져 경쟁이 실제보다 적게 계산된다.
- **옆 지역 자료가 없는 곳:** 자료를 만든 옆 지역만 센다. 안산·양평·목포는 경계 근처 칸이 옆 지역 가게를 놓친다. 전국을 만들면 해결된다.
- **지역 불러오기 시간:** 청주처럼 큰 지역은 불러올 때 몇 초 걸릴 수 있다(Node 기준 2.7초).
- **기준값 하나:** 서울·시골에 같은 값을 쓴다(사용자: 일단 괜찮음).
- **산업단지 이름:** 이름이 빈 곳이 많아 종류로 나온다.
- **분홍 묶음 테두리:** 넓게 볼 때 덩어리 안 어느 칸이 넘었는지는 확대해야 안다.

## 함정

- **인구 API:** 리 코드로 물어도 읍·면 전체가 온다. 읍·면 코드(끝 00)로 한 번만 묻는다. `lv=3`은 법정동 합계, `lv=4`는 통·반 행. 시군구 코드(`...00000`)로 `lv=4`를 물으면 NODATA. 새 코드로 과거 달을 물으면 옛 코드 행이 온다(목포 46110).
- **API 빈 응답:** 정상 응답(`resultCode 0, 정상`)과 똑같이 빈 결과가 올 때가 있다. 반드시 재확인한다.
- **하루 한도:** 초과 시 본문에 `LIMITED_NUMBER_OF_SERVICE_REQUESTS` 또는 HTTP 429. `QuotaError`로 처리한다.
- **백그라운드 수집:** 실행 중인 수집은 그 뒤 고친 코드를 쓰지 않는다. 고친 뒤에는 해당 raw를 치우고 다시 받는다. Claude 세션이 끊기면 백그라운드 실행도 끊길 수 있다(세종 판정이 그렇게 멈춤).
- **브라우저 그리기:** 작은 캔버스를 CSS로 100배 늘리면 어긋난다. `Path2D`나 캔버스 경로 하나에 수만 개를 넣으면 크게 느려진다(3만 8천 칸 7.5초). 수백 개씩 나눠 칠한다.
- **gridAt:** 지역 범위 밖 점을 넣으면 계산이 흩어진다. 범위 밖이면 바로 '칸 없음'으로 돌려준다.
- **Claude 브라우저:** 창이 숨겨지면 `requestAnimationFrame`이 멈춰 칸이 안 그려진다. 시험할 때 `window.requestAnimationFrame = fn => setTimeout(fn, 0)`. 콘솔 메시지는 새로고침해도 예전 것이 남아 보일 수 있어 `window.addEventListener('error', ...)`로 새로 모은다. `mobile` 크기는 터치 흉내라 지도 칸 클릭이 안 된다(790px 폭에서 시험). 지도를 두 번 누르면 확대가 아니라 칸이 선택된다(확대는 휠이나 + 버튼).
- **편집 도구:** 바꿀 문자열 끝의 공백이 빠질 때가 있었다(" · " → " ·"). 고친 뒤 화면 글자로 확인한다.
- **명령 줄의 긴 파이썬:** 따옴표가 섞이면 bash heredoc이 깨진다. 임시 폴더에 스크립트 파일로 저장해 실행한다.
- `check.mjs`는 HTML의 `// ---------- 설정`~`// ---------- 지도` 구간만 Node에서 돌린다. 그 구간에 `window`·`document`·`naver`를 쓰면 검사가 깨진다.
- 시험 서버(`.claude/launch.json`의 `ansan-map`)를 켜 둔 채 끝내면 `실행.bat`과 포트 8765가 겹친다. 확인 후 끈다.
- `입지조사/index.html` 화면의 API 키 저장 기능을 쓰면 `설정.env`의 다른 키가 지워질 수 있다. `수집/check_keys.py`는 안 쓰는 키를 시험한다.
- 브이월드 사이트는 Claude 브라우저를 막는다. Claude 도구로 네이버 도메인을 열 수 없다.
- 법령 원문은 Claude 브라우저로 `https://www.law.go.kr/법령/<법령명>`을 열고 iframe 안 글자를 읽는다. 공공데이터포털 API 명세는 상세 페이지 HTML의 `swaggerJson`.
- 선배에게 줄 주소는 `https://cake-map-ansan.pages.dev`. 선배 이메일 추가: Zero Trust → Access controls → Applications → `cake-map-ansan-main` → Edit → Include에 `Emails`. 이메일은 사용자가 직접 입력한다.
- 기존 ChatGPT 배포 사이트는 가짜 데이터 버전이다. 공개 범위를 바꾸지 않는다.
- `python -I`로 실행하면 출력이 깨진다. `sys.stdout.reconfigure(encoding="utf-8")`.
- 확대 단계를 말할 때 숫자 대신 "지금보다 한 단계 더/덜"로 확인한다.
